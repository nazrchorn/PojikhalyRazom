# Рефакторинг RegistrationScreen

## 📋 Проблема
Екран реєстрації мав змішану логіку:
- ❌ Валідація розкидана по кодуть методів
- ❌ Однопаша форма — гаряча UX
- ❌ Кольори жорстко закодовані у кожному віджеті
- ❌ Складність форми — 5 полів одразу
- ❌ Брак зворотного зв'язку (feedback) при помилках

---

## ✅ Рішення: Multi-Step Registration (3 кроки)

### 1️⃣ **Видобута класу RegistrationFormValidator**

```dart
class RegistrationFormValidator {
  static String? validateEmail(String? value) { ... }
  static String? validatePassword(String? value) { ... }
  static String? validatePhone(String? value) { ... }
  static String? validateRequired(String? value) { ... }
}
```

**Переваги:**
- ✅ Можна одержані в тестах
- ✅ Чистота (SRP — один клас = одна відповідальність)
- ✅ Переюсь в інших форм

---

### 2️⃣ **Архітектура 3-кроків (Multi-Step)**

#### **Крок 1: Облік (Email + Пароль)**
```
┌─────────────────────────┐
│  Email                  │
│  Пароль (мін. 6 сим.)   │
└─────────────────────────┘
```
- Фокус: назив облік
- Валідація: Email, Password
- Кнопка: "Далі"

#### **Крок 2: Особисто (Ім'я, Телефон, Дата)**
```
┌─────────────────────────┐
│  Ім'я                   │
│  Телефон                │
│  Дата Народження | Стать│
└─────────────────────────┘
```
- Фокус: особисті дані
- Валідація: Required, Phone
- Кнопки: "← Назад" | "Далі →"

#### **Крок 3: Перевірка**
```
┌─────────────────────────┐
│  Email: user@test.com   │
│  Ім'я: John Doe         │
│  Телефон: +380675555555 │
│  Стать: Чоловік         │
│  Дата: 15.05.2000       │
└─────────────────────────┘
```
- Фокус: про вторення перед реєстрацією
- Кнопки: "← Назад" | "✓ Створити акаунт"

---

### 3️⃣ **UI Компоненти**

#### **Прогресс-бар**
```
┌─────────────────────────┐
│  ①    ②    ③            │
│ Облік > Особисто > Під  │
└─────────────────────────┘
│████░░░░░░░░░░░░░░░░░│ 33%
```
- Показує поточний крок (1/3)
- NumericCircles з номерами/галочками
- Linear progress indicator знизу

#### **Повідомлення про помилки**
```
⚠️ Помилка: Введіть коректний email
```
- Червоний контейнер з іконкою
- Видимо тільки кеогда є помилка
- Очищується при переході на наступний крок

#### **Кнопки навігації**
```
[← Назад] [Далі →] або [← Назад] [✓ Створити]
```
- "Назад" — неактивна на кроці 1
- "Далі" — перевіряє форму поточного кроку
- "Створити" — завершує реєстрацію

### 4️⃣ **Тематичні кольори (константи)**

## 🏛️ Clean Architecture

### Розділення відповідальності:

```
┌─────────────────────────────────────┐
│ UI Layer (registration_screen.dart) │
│ • Render (IndexedStack, TextFields) │
│ • State navigation (_currentStep)   │
└─────────────────────────────────────┘
           ↓ uses
┌─────────────────────────────────────┐
│ Service Layer (AuthService)         │
│ • registerUser()                    │
│ • Firestore + Firebase Auth access  │
└─────────────────────────────────────┘
           ↓ uses
┌─────────────────────────────────────┐
│ Validator (RegistrationFormValidator)
│ • Static validation methods         │
│ • No context, no state              │
└─────────────────────────────────────┘
```

## 🔍 Як це вумопевана для захисту

Коли професор відкриє код, він побачить:

✅ **Single Responsibility:**
- Кожен метод (_buildStep1, _buildStep2) — один крок
- Валідація — окремий клас
- Navigation — окремі методи (_nextStep, _previousStep)

✅ **Clean Architecture:**
- UI → Service → Firebase (однісний потік)
- Логіка валідації — читка і тестабельна

✅ **UX/UI Best Practices:**
- Прогресс-бар показує поточний стан
- Помилки показуються інтуїтивно
- Форма розбита на manageable кроки

✅ **Кодова якість:**
- Константи для кольорів (не жорстко закодовано)
- Никного дублювання
- Назви методів清ясні (camelCase, без double-underscore)

## 📝 Використання

```dart
// Користувач натискає "нема аккаунту? створи"
Navigator.of(context).push(
  MaterialPageRoute(
    builder: (context) => const RegistrationScreen(),
  ),
);

// Екран 1: Вводить email + пароль
// Екран 2: Вводить ім'я, телефон, дату
// Екран 3: Переглядає дані і натискає "Створити"
// → AuthService.registerUser() → Firestore + Auth creation
// → Екран переходить на /main (home)
```
