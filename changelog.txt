Перелік функцій мінімальної версії
- Реєстрація: через телефон, email або соцмережі
- Профіль користувача: фото, ім’я, контактні дані
- Пошук поїздок: за маршрутом, датою та кількістю місць
- Бронювання: простий процес у кілька кліків
- Оплата: готівка
- Рейтинг та відгуки: оцінка поїздки (зірки) + короткі коментарі
- Комунікація: чат у застосунку та push-сповіщення
- Безпека: верифікація телефону, можливість скарги на користувача
- Підтримка: email або чат-бот для допомоги

🚀 Додаткові функції (на другий етап)
- Геолокація та інтеграція з картами.
- Динамічне ціноутворення (залежно від попиту).
- Розширена перевірка водіїв (ID, страховка).
- Програма лояльності або бонуси.

Таким чином, MVP має бути максимально простим: пошук → бронювання → оплата → поїздка → відгук.

Де зберігати реєстраційні дані, Варіанти:
Реляційна база даних (SQL)
- Приклади: PostgreSQL, MySQL
NoSQL база даних
- Приклади: MongoDB, Firebase Firestore
Хмарні сервіси
- Приклади: Firebase, AWS DynamoDB, Supabase
Вибираємо використовувати Google Cloud (Firebase Firestore). Це найзручніший варіант для MVP, бо Firebase входить до 
Google Cloud і має готові SDK для Flutter.
Firebase має власний безкоштовний план (Spark Plan):
- Firestore: 50k читань/записів/видалень на місяць.
- Authentication: до 10k користувачів.
- Hosting: 1 ГБ зберігання + 10 ГБ трафіку.
- Це дуже зручно для мобільних застосунків і MVP.
